# Информационный бот лаборанта

Консольная программа на C++ для справочной информации о работе лаборанта, учета рабочего времени и регистрации сообщений об инцидентах в кабинете ИКТ.

## Сборка в PowerShell

Перед компиляцией добавьте папку UCRT64 MSYS2 в `PATH` текущего окна PowerShell, чтобы компилятор нашел свои DLL:

```powershell
$env:Path = "C:\msys64\ucrt64\bin;$env:Path"
g++ -std=c++14 -Wall -Wextra -Wpedantic .\main.cpp -o .\program.exe
.\program.exe
```

## Code Review & Vulnerability Analysis

Ниже описаны дефекты, найденные в предоставленной версии СРС#2, и их исправления в текущей версии `main.cpp`. Проверка поведения не заменяет фактические кадровые и инвентарные документы.

### 1. Конец ввода мог зациклить программу

**Проблема.** Старые циклы после `cin.fail()` очищали состояние потока и снова запрашивали значение, не завершаясь при EOF.

**Последствие.** При закрытом или перенаправленном вводе программа могла бесконечно выводить запросы.

**Исправление.** `readInt()` и `readDouble()` читают строку целиком, распознают EOF и передают его вызывающему сценарию для штатного завершения.

### 2. Меню не обрабатывало текст вместо числа

**Проблема.** В исходном `main()` результат `cin >> choice` не проверялся. После ввода `abc` поток оставался в ошибочном состоянии.

**Последствие.** Выбор меню становился непредсказуемым, а повторное чтение могло не работать.

**Исправление.** Меню использует `readInt()`; ошибочная строка отклоняется целиком и запрашивается повторно.

### 3. Контрольный вопрос также принимал некорректный ввод

**Проблема.** Для `answer` не было проверки ввода, поэтому текст вместо числа ломал сценарий проверки ответа.

**Последствие.** Пользователь мог не иметь возможности ввести правильный ответ после ошибки.

**Исправление.** Ответ читается через `readInt()`, а неверное число запрашивается повторно; EOF корректно завершает программу.

### 4. Не проверялись разумные пределы параметров графика

**Проблема.** Первоначальная проверка требовала только положительные числа. Значения вроде 100 рабочих дней, ставка 3 или 200 часов в день проходили.

**Последствие.** Расчет выдавал бессмысленные недельные нормы и дефициты.

**Исправление.** Текущая версия ограничивает число рабочих дней диапазоном 1–7, ставку — `(0, 1]`, а часы в день — `(0, 24]`. Номер ноутбука проверяется на положительность; наличие конкретного номера определяется только по инвентарному реестру.

### 5. Проверка рабочего времени завершалась по значению `hours == 4`

**Проблема.** В исходном модуле недельная норма рассчитывалась как `40 * rate`, но цикл прекращался при четырех часах в день независимо от числа рабочих дней. Для четырехдневной недели и ставки 0,5 это означало 16 часов при норме 20.

**Последствие.** Программа могла показать дефицит и затем ошибочно сообщить, что норма подтверждена.

**Исправление.** Текущий модуль сравнивает рассчитанное количество часов в неделю с нормой с небольшим допуском и продолжает запрос, пока норма не достигнута. При недостатке часов выводится предусмотренная учебным заданием фраза о заведомо ложных сведениях; сам расчет дефицита не устанавливает намерение или виновность.

## Выписка из Устава

Модуль дисциплинарных взысканий приводит пункт 3.3.6 Устава АО «Академия гражданской авиации» (страница с печатной нумерацией 3): «участие в организации и проведении фундаментальных и прикладных научных исследований и иных научно-технических и опытно-конструкторских работ по проблемам гражданской авиации, в том числе по проблемам образования, совершенствования учебно-воспитательного процесса в Обществе».

Это положение описывает направление деятельности Общества, а не персональную обязанность лаборанта и не самостоятельное основание для взыскания. Решения о нарушении и мерах принимаются уполномоченными лицами после проверки фактов и применимых локальных актов.

## Протокол реагирования

Протокол сохраняет учебные задержки `sleep_for` и перечисляет отдельные действия: проверить сообщения о выносе ноутбука, возможной утере блока питания и отказе от подготовки/тестирования ПО; запросить аудит записей камер и сверить журнал посещений; уведомить ответственного за кабинет ИКТ; направить служебную записку заведующему кафедрой, руководителю конструкторского отдела и декану факультета; рассмотреть дисциплинарную комиссию и передачу материалов в материальный учет. Перечисленное обозначено как требующее проверки, а не как автоматически доказанные факты.
